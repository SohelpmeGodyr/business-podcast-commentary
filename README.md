# Business Podcast Commentary

一套用于分析商业播客和长访谈的 Agent Skill：把大段逐字稿重构为陌生读者也能理解、有证据边界、可用于判断的深度商业评述。

它依次回答五个问题：

1. 这期内容到底讲了什么，论证怎样展开？
2. 嘉宾提出了哪些重要判断？
3. 哪些外部事实能够得到公开来源支持？
4. 商业机制、关键约束和利益分配是什么？
5. 从前后说法里还能读出哪些隐性信号，接下来怎么判断？

## 它解决什么问题

- **内容还原**：先建立主题、案例、背景、限定条件和行动建议的覆盖地图，防止为了精炼而漏掉重要信息。
- **陌生读者可理解**：成品不假设读者听过播客，保留理解结论所需的论证过程和关键例子。
- **大白话写作**：分析过程可以复杂，成文优先使用原话和常用词；专业词第一次出现时立即解释。
- **事实核查**：识别会影响核心结论的承重事实，搜索并打开独立来源进行验证。
- **商业分析**：拆解投入、生产、分发、获客、变现、结算、瓶颈和利益分配。
- **证据分层**：明确区分“嘉宾的说法”“暂时查不到公开证据的内部信息”“我们的判断”“事实状态”和“隐性信号”。
- **隐性信号二次扫描**：初稿完成后重新通读逐字稿，专门检查前后矛盾、数字选择、异常强调、刻意回避和高成本选择。
- **混合标注**：重大错误或存疑就地短提示，一般核查只显示编号，完整证据统一放在文末。
- **多格式交付**：支持 Markdown/Obsidian、Word `.docx` 和飞书文档。

## 适合分析什么

- 商业播客、创始人访谈、投资人对谈
- 财报电话会、行业圆桌、长篇商业讨论
- 需要事实核查、经营视角或投资视角的逐字稿

它不适合单纯语音转写、娱乐内容摘录或只有几句话的简单摘要。

## 快速开始

### 1. 下载完整仓库

下载后保留完整目录，不要只复制 `SKILL.md`；核查、证据、推演和多格式规则位于 `references/`。

### 2. 放入 Skill 目录

常见位置：

```text
Claude Code: ~/.claude/skills/business-podcast-commentary/
Codex:       ~/.codex/skills/business-podcast-commentary/
```

Windows 中的 `~` 代表当前用户目录，例如：

```text
C:\Users\你的用户名\.claude\skills\business-podcast-commentary\
```

### 3. 调用

最简单的调用方式：

```text
使用 $business-podcast-commentary 分析这份商业播客逐字稿。
```

未指定文件格式时，默认输出标准 Markdown，可直接放入 Obsidian 或其他 Markdown 阅读器。

针对不同编辑器，可以直接说明：

```text
使用 $business-podcast-commentary 分析这份逐字稿，输出为适合 Obsidian 的 Markdown。
```

```text
使用 $business-podcast-commentary 分析这份逐字稿，生成 Word 文档。
```

```text
使用 $business-podcast-commentary 分析这份飞书逐字稿，并把评述写入飞书文档。
```

## 默认成品结构

1. 摘要与阅读导向
2. 这期到底讲了什么
3. 按主题进行内容还原与分析
4. 商业机制、赢家、约束与风险
5. 隐性信号与后续观察
6. 事实核查与证据台账
7. 原始逐字稿全文

完整逐字稿默认放在文末并保持展开，但正文必须能够脱离逐字稿独立阅读。

## 三种交付格式

### Markdown / Obsidian

使用标准标题、引用、表格和链接。只有明确要求 Obsidian 时才使用 Obsidian callout，不擅自创建不存在的内链、标签或知识库目录。

### Word

生成真实的 `.docx` 文件，而不是给 Markdown 改后缀。标题、引用、表格和分页需要经过逐页渲染检查，确认没有缺字、裁切、重叠或异常分页后再交付。

### 飞书

只有在用户明确要求时才写入飞书。需要可用的 `lark-doc` 能力和用户授权；颜色、callout、表格或画板只在确实降低理解成本时使用。

## 使用要求

- 必须提供逐字稿、访谈文本或 Agent 可以读取的源文档。
- 事实核查需要 Agent 具备网页搜索和打开原始来源的能力。
- Word 输出需要可用的文档生成与渲染能力。
- 飞书写入需要可用的 `lark-doc` 能力以及用户授权。
- 本仓库不包含 API Key、Token、私人逐字稿或个人知识记录。

## 重要边界

公开来源支持某项说法，不代表来源绝对正确。隐性信号是基于有限材料作出的分析，不是事实认定，也不是对个人动机下结论。每条信号都应说明为什么这样判断、还有什么其他可能，以及接下来该看什么。
