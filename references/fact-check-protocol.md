# 事实核查与交叉验证协议

在通读逐字稿后、建立主张台账前使用本协议。目标：将播客中仅来自说话者单方陈述的事实主张，与公开独立来源进行比对，让读者看到"谁说了什么"和"独立可确认什么"两个层面。

## 核心原则

播客逐字稿能确认一件事：**说话者说了这句话**。说话者在话中引用的外部事实——数字、时间线、市场份额、因果归因、凭记忆引用的历史事件——需要独立来源复核。

在核查完成前，所有事实性断言保留为"说话者主张"，不在正文中静默改写为确定事实。

## 承重度判定

不是所有事实主张都需要同等深度的核查。提取每条主张时，先判定承重度——承重度决定查不查、查多深、在正文中怎么标。

| 承重度 | 定义 | 判断标准 | 核查深度 |
|---|---|---|---|
| `承重` | 这条错了，评述的核心结论需要改写 | 直接支撑步骤 4 那 3—5 个承重主张中的至少一个 | 进入核查批次。正文中必须带核查状态标签 |
| `支撑` | 强化某个论点，但错了不会推翻结论 | 出现在论证链条中，但不是链条的根 | 不进入核查批次。正文中标注"据 XX 称"。有特别需要时可补查 |
| `背景` | 点缀、举例、过渡性叙述 | 删掉它不影响任何商业判断。说话者明确用了"我记得""大概""好像"等模糊措辞 | 不进入核查批次。正文中标注"据 XX 称" |

### 判定规则

**判为承重**（满足至少一条）：
- 它是某个承重主张的直接数值证据（如"营收 41.6 亿"支撑"该品牌是赛道第一"）
- 它是某个因果链的核心变量（如"抽成比例从 30% 降到 15%"解释了"为什么创作者涌入"）
- 它是某个判断的排除条件（如"全行业只有三家在认真做"错了，"赛道格局分散"这个结论就站不住）

**判为背景**（满足任意一条即可）：
- 说话者明确使用了模糊措辞（"我记得""大概""当时好像是"）
- 数字是孤立的、与本期的核心商业问题无关
- 涉及的公司或事件不在本期论证链条中

**其余默认判为支撑。**

承重度决定核查深度，不决定可信度。背景级主张不被核查不等于它错了，只等于"不值得查"。

## 提取：从逐字稿到核查清单

逐条记录，每条保留原话，不概括、不润色：

| 字段 | 说明 |
|---|---|
| 编号 | F-01, F-02 … |
| 原话 | 逐字稿完整原句 |
| 说话者 | 谁说的，在行业中的位置 |
| 时间戳 | 逐字稿位置 |
| 主张类型 | 量化 / 时序归因 / 回忆性 / 竞争判断 / 政策断言 |
| 承重度 | 承重 / 支撑 / 背景 |
| 可验证问题 | 拆为 1—3 个可通过公开资料回答的具体问题（承重和支撑级填写，背景级可选） |

以下不需要核查：说话者对自己企业当前做法的描述（这是一手信息）、主观判断和预测（不是事实主张）、关于自身经历的非量化叙述。

## 核查：搜索与比对

### 搜索

每个可验证问题执行至少两次搜索，**从不同角度切入，使用不同信息类型**——不是把同一个关键词换个说法再搜一遍。至少包含一次直接验证（公司官方披露/招股书/年报）和一次反向验证（搜索可能矛盾的信息）。搜索时必须打开原始来源页面确认数字，禁止只看搜索结果摘要就引用。

**搜索透明**：每条核查记录必须包含搜索日期、使用的搜索工具、实际使用的搜索词。记录的目的是让使用者可以自行复现搜索过程、判断搜索词是否恰当。

**负结果记录**：搜了什么、怎么搜的、为什么没搜到——同样写入核查记录。"没搜到"本身是信息，不是失败。

### 判断来源独立性

这条规则直接取自 PR Builders Follow 的趋势模型："多家媒体转述同一新闻稿只算一项证据。"

5 篇文章都引用同一份公司新闻稿 → 算 1 个独立来源，不是 5 个。来源独立性按**信息源头**判断，不按转载次数。

### 来源可信度与记录

每条核查来源必须记录以下最低字段：**发布主体、发布日期、来源类型、原始链接。** 填不出这些字段的来源不算合格证据。

来源可信度按以下优先级判断：

| 级别 | 来源类型 | 说明 |
|---|---|---|
| 一手 | 公司年报、招股书、监管文件、法院文书、官方统计 | 审计或备案数据，最可信 |
| 二手 | 权威媒体独立调查、经审计的行业报告 | 独立采写，有编辑审核 |
| 三方估算 | QuestMobile、极光、艾瑞等第三方监测 | 样本推算，非全量统计 |

第三方监测数据有内在方法论局限——口径不透明、样本有偏差、未经审计。核查结论中必须注明其局限性。优先用一手来源，搜不到一手的可以用三方数据，但必须明确标注"该数据来自第三方监测机构，基于样本推算，非一手来源，仅供参考"。不得把三方估算当成铁证来写。

### 同一来源禁用

**同一 URL 只能用于验证一条承重主张。** 同一个 QuestMobile 数据页不能用来验证 A、B、C 三条不同的主张——这等于一个来源当了三次证据。每个承重主张的核查必须有不同来源支撑。如果搜来搜去只有同一个数据商的页面，诚实标注"多个主张的核查依赖于同一第三方数据源，交叉验证不充分"。

### 核查信心

核查信心不取决于来源的"权威等级"，而取决于独立来源的**数量和多样性**：

| 标签 | 条件 | 含义 |
|---|---|---|
| `✅ 已确认` | 2 个及以上独立来源，口径一致 | 多个独立信息源头指向同一事实 |
| `⚠️ 部分确认` | 1 个独立来源，或 2+ 个来源但口径有差异 | 方向一致，细节不完全匹配 |
| `🔍 无法验证` | 0 个独立来源 | 可能属于说话者的一手经营信息，也可能无人记录 |
| `❌ 存疑` | 独立来源与该主张明显矛盾 | 存在可信反证 |

"独立来源"指信息源头不同——两份不同的年报、两家不同的媒体各自独立采写、一份年报加一份行业报告。同一新闻稿的转载、同一数据的多处引用，均不算独立来源。

### 无法验证分层

`🔍 无法验证` 不等于"这个数据是假的"，也不等于"这个数据多半不靠谱"。必须根据说话者与数据的距离，在核查结论中标注层级：

| 层级 | 标记 | 含义 | 示例 |
|---|---|---|---|
| 一手经验 | `[一手经验]` | 说话者亲身经手的数据，他是一手来源，只是没有对外公开 | "我管的预算权限是 X"——查不到正常，可信度不低 |
| 内部信息 | `[内部信息]` | 说话者从内部知道的、非本人直接负责的数据，可能有渠道知道但不是一手 | "整个公司的增长预算是 X"——他不是 CEO，这个数字他从别人那听来 |
| 外部判断 | `[外部判断]` | 说话者对外部世界的判断或引用，他跟听众一样是二手 | "行业平均 ARPU 是 X""某竞品的数据是 Y"——查不到就真的没什么可信度 |

核查结论中标注示例：`<span text-color="orange">🟡 经核查，未找到独立公开来源证实。该数据属于说话者的一手经验，无法通过公开渠道核实。</span>`

### 多人交叉印证

如果本期播客有多个说话者，核查时检查他们之间是否存在印证或矛盾：
- A 和 B 对同一数据给出了相近的说法 → 标注"本期说话者 A 与说话者 B 的数据互相印证，两位独立说话者指向同一事实，可信度高于单人陈述"
- A 和 B 对同一数据给出了矛盾的说法 → 标注"本期说话者 A 与说话者 B 的数据存在矛盾，标为待解决争议"

### 记录核查过程

每条进入核查的主张记录：搜索日期、使用的搜索工具、实际使用的搜索词、找到的来源 URL、来源最低字段（发布主体、发布日期、来源类型）、来源独立性判断、核查结论、一句话理由。**搜索词和搜索过程必须写得足够详细，让使用者可以自行复现。** 没搜到的也要记录——说明用了什么搜索词、搜了几个角度、为什么没找到。

## 核查批次控制

### 分批执行

每批最多 10 条。按承重度排序（承重优先），同级按在论证链条中的位置排序（核心结论依赖的在前）。

每批核查完成后，**不在对话中输出摘要**——而是将核查结果直接写入文档正文。所有承重主张核查完毕或用户确认停止后，剩余的 `⚠️ 未经核验` 标签统一代表"确实查不到"而非"还没查"。

### 承重主张被跳过前的安全网

用户要求停止核查、但还有承重级主张未进入批次时，必须提示：

```
⚠️ 还剩 N 条承重级主张未核查。评述的核心结论将建立在不完全验证的基础上。

确定跳过？还是只查剩余承重条目？
```

用户确认后才可跳过。

## 正文内嵌标注

核查结果不放在附录等读者去找——而是直接写在正文中每处事实主张出现的位置。

以下数字和主体均为格式演示用的虚构示例，实际输出必须替换为逐字稿原话与真实来源。

**格式规则：说话者原话与核查结论必须泾渭分明。** 先完整写出说话者的原话（黑色正文）。然后另起一行、单独一段，用 `<span text-color="...">` 带颜色的文字写出核查结论。核查结论禁止和说话者原话放在同一段内。

**核查只针对说话者原话。** 彩色核查结论只能出现在说话者的直接引用之后。agent 自己的分析、推演、总结不允许加核查标签——agent 不能自己编一个判断然后自己"验证"它。如果正文中出现 agent 的分析性判断，必须标注"编辑分析"且不得附加核查颜色。

文字颜色使用飞书 XML 的 `<span text-color="色名">` 语法：已确认用 `green`，部分确认或无法验证用 `orange`，存疑用 `red`。飞书 XML 不使用 CSS 十六进制色值。必须实际改变文字颜色，不能只在文字前加 emoji。

### 承重级标注

**已确认**：

> 张某在访谈中提到，该品牌 2022 年营收达 48 亿元。<span text-color="green">🟢 经核查，该公司 2022 年报披露营收为 41.6 亿元，方向一致。张某的数字略有向上取整。来源：公司 2018 年报、2022 年报（示例省略链接，实际输出必须附原始链接）。</span>

**部分确认**：

> 张某称五年营收翻了 12 倍。<span text-color="orange">🟡 经核查，2018 年营收 3.2 亿元，2022 年营收 41.6 亿元，实际增长约 13 倍。方向一致，张某略有向上取整。来源：公司年报（示例省略链接，实际输出必须附原始链接）。</span>

**无法验证**：

> 张某在访谈中提到，该品牌 2022 年营收达 48 亿元。<span text-color="orange">🟡 经核查，截至发稿未找到独立公开来源证实该数据。该数字来自张某单方陈述，无法独立核实。</span>

**存疑**：

> 张某称该品牌为"全行业第二"。<span text-color="red">🔴 经核查，公开数据显示至少 3 家同业公司营收规模更大。张某的表述与公开信息存在矛盾。详见事实核查板块。</span>

### 支撑级和背景级标注

不进入核查批次，正文中统一在说话者原话后标注"（据 XX 在访谈中称）"。不出现颜色标签。

### 标注原则

- 凡是承重级事实主张，正文中说话者原话后必须紧跟核查结论（带颜色文字）。无核查结论 = 漏标，质量检查时捕获。
- 核查结论使用飞书 XML `<span text-color="green">` / `<span text-color="orange">` / `<span text-color="red">` 改变文字颜色。飞书只支持命名色，不支持 hex 色码。**禁止只加 emoji 不用 span——等同于未完成核查。**
- 核查结论必须包含核查动作（搜了什么）、核查结果（找到什么/没找到什么）、局限性（如果有）。
- 核查状态只在事实主张第一次出现时标注，后续重复提及可用"前述已确认"省略。

## 事实核查板块

`🔎 事实核查` 板块置于正文之后。包含两部分：

**一、说话者核查成绩单**（表格，置于板块最上方）：

| 说话者 | 承重主张数 | 已确认 | 无法验证 | 存疑 | 主要可信来源类型 |
|---|---|---|---|---|---|

表格下方用一两句话总结该说话者整体可信度：哪些类型的数据被证实了、哪些无法验证、整体画像。不给抽象评分，只说具体结论。例如："张某对所在业务的一手经营数据（预算权限、团队规模）多为无法验证但属于其一手经验；其引用的外部市场数据多数能被公开来源确认。"

**二、多人印证/矛盾**（成绩单之后）：如果本期有多位说话者，检查同一数据点是否被多人提到——互相印证或互相矛盾，标注出来。

**三、逐条核查记录**（最后）：只收录承重级主张的完整核查记录（原话引用 → 核查发现 → 独立来源链接 → 结论），支撑级和背景级不收录。核查板块的内容与正文中的颜色标签一一对应。

## 可证伪条件

每条"已确认"或"部分确认"的核查结论，写一句"什么证据会推翻它"。

示例：如果确认的依据是公司年报，可证伪条件可能是"如果该公司后续因财务重述修订了该年份数据"。

## 核查边界声明

核查完成时，在事实核查板块末声明：
- 总共提取了多少条事实主张、承重/支撑/背景各多少条
- 承重级中已核查多少条、未进入核查批次多少条及原因（用户跳过 / 搜索工具限制）
- 搜索日期、使用的搜索工具、搜索覆盖范围声明
- 核查只能确认"有公开来源支持"，不能保证公开来源本身无误
- 第三方监测数据使用情况：哪些数据依赖三方估算、哪些有独立一手来源
- 同一来源复用情况：是否存在一个来源验证多条主张的情况
- 说话者的一手经营信息（内部数据、未公开策略）无法核查，不做真伪判断
